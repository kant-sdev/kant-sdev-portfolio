# Internacionalização

O portfólio utiliza `pt-BR` como padrão e oferece `en`, sem bibliotecas ou serviços de tradução. As rotas e os links são os mesmos nos dois idiomas.

## Conteúdo e dados

- `data/i18n/pt-BR.ts` é a fonte de conteúdo editorial em português e define o tipo `Dictionary`.
- `data/i18n/en.ts` implementa esse mesmo tipo. Uma chave ausente ou incompatível gera erro no TypeScript.
- `data/i18n/index.ts` reúne os dois dicionários.
- Navegação, tecnologias, projetos e contatos continuam nos arquivos existentes em `data/`. Seus IDs ligam os dados aos textos traduzidos; nomes oficiais, imagens, URLs, slugs e repositórios não são traduzidos.
- `getProjects(locale)` e `getFeaturedProjects(locale)` combinam os dados dos projetos com as descrições e categorias do idioma selecionado.

Para acrescentar conteúdo, adicione a chave nos dois dicionários e use `useLocale().content` no componente. Para novos projetos, acrescente o registro em `data/projects.ts` e o texto correspondente em `projects.items` nos dois idiomas. O TypeScript verifica a cobertura dos IDs de projetos, categorias e navegação.

As estruturas vazias de skills, experiências e trajetória não foram preenchidas artificialmente. Novas páginas podem seguir o mesmo padrão de IDs e dicionários, dentro do provider já existente, sem um novo estado de idioma.

## Estado e persistência

`LocaleProvider`, no layout raiz, compartilha o idioma com toda a aplicação. O seletor acessível do Header altera esse estado sem recarregar a página ou remontar as seções.

O armazenamento utiliza a chave `kant-sdev:locale` em `localStorage`. A preferência é lida após a hidratação, quando React assina o estado via `useSyncExternalStore`. O servidor e a primeira renderização do cliente usam sempre `pt-BR`: não há leitura de `window` durante SSR nem necessidade de `suppressHydrationWarning`.

Com uma preferência salva, o HTML inicial em português é atualizado após a hidratação. A aplicação mantém o idioma durante a navegação, sincroniza alterações entre abas e continua funcionando em memória quando o navegador bloqueia o armazenamento. Sem armazenamento, a preferência não sobrevive a uma recarga.

O atributo `html.lang` acompanha o idioma. O formulário guarda códigos de erro, e não mensagens já traduzidas, para atualizar erros existentes sem apagar os campos. O carrossel mantém o projeto selecionado ao alternar idioma. As animações existentes permanecem, com `MotionConfig` respeitando a preferência de movimento reduzido.

## Metadata e páginas futuras

Os dicionários incluem título e descrição para Home, projetos, detalhe de projeto, mapa técnico, trajetória e 404. `LocalizedMetadata` renderiza as tags nativas do React 19, que são posicionadas em `head` tanto no SSR quanto na navegação. Cada página existente renderiza uma instância; não duplique essas mesmas tags em `metadata` do layout ou da página.

`getPageMetadata(page, locale)` está disponível para uma futura integração com a Metadata API do Next.js quando o idioma também for conhecido pelo servidor. Hoje, a preferência é exclusivamente da aplicação: robôs que leem somente o HTML inicial recebem metadata e conteúdo em português. Não há URLs localizadas, cookies de idioma ou redirecionamentos.

`/projects` e `/trajectory` continuam sem páginas próprias. Foram traduzidos apenas os avisos já existentes em `/projects/[slug]`, `/technical-map` e a página 404.

## Validação

Com Node.js 24 e as dependências já instaladas:

```sh
pnpm test:i18n
node node_modules/typescript/bin/tsc --noEmit
pnpm lint -- app components/i18n components/layout components/not-found-content.tsx components/sections components/ui/technology-tag.tsx data lib/i18n tests/i18n.test.mjs types/projects.ts
pnpm build
```

Os testes cobrem paridade e preenchimento dos dicionários, IDs, nomes e links de projetos, metadata, valor inicial de SSR, restauração da preferência, valores inválidos, armazenamento bloqueado e sincronização entre abas.

Na interface, confira a troca de idioma, navegação e retorno à Home, recarga, menu móvel, teclado, carrossel, erros de validação, preservação dos campos e ausência de avisos de hidratação. O formulário continua sem endpoint: o aviso de indisponibilidade foi traduzido, mas nenhum serviço de envio foi integrado.
